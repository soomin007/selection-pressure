## 왜 만드나 (한 문단)

탭 조종을 넣어도 "여전히 딱히 재미가 없다"(2026-08-03 폰 실기). 원인은 조종이 아니라 **판정 부재**다.
관전 16초가 아무 질문에도 답하지 않는다. 롤토체스의 30초 전투가 재미있는 이유는 "내가 방금 짠 조합이
이기는가"라는 질문 하나에 답하기 때문. 처방은 라운드마다 ① 미리 보이는 시험 ② 합격/불합격 판정
③ 지면 아프되 런이 끝나지는 않는 대가(부분 패배)를 붙이는 것. 조종은 버리지 않는다 — 탭 지시는
이 판정을 수행하는 손이 된다(롤토체스의 "배치"에 해당).

## 루프 한 바퀴 (만드는 것 전부)

```
드래프트: "다음 라운드: 사냥 2회" 예고   ← 카드 선택이 목표를 얻는다 (④)
   ↓ 카드 선택
관전(16초): goalBar "이번 시험: 사냥 2회 (1/2)" 실시간 진행   ← 화면을 볼 이유 (①)
   ↓ 라운드 끝
판정: 합격(라임 플래시) / 불합격(호박 플래시 + "사냥 1/2 — 불씨 1을 잃었습니다")
   ↓
불씨 사다리: ●●●○○ — 0이 되면 런 종료   ← 지면 아프되 안 끝난다 (②)
```

## A. 시험(라운드 목표) — forage 단계에만 새로 만든다

보스·멸종 단계는 시험을 새로 만들지 않는다 — **그 단계 자체가 이미 시험**이다(격퇴=대성공, 생존=합격).

**시험 후보 4종** (빌드에 따라 후보 필터 — 못 하는 시험을 내면 안 된다):

| id | 문구(예) | 합격 조건 | 후보 자격 |
|---|---|---|---|
| hunt | 사냥 2회 성공 | roundCounts.hunts ≥ N | genome.diet > SIM.dietHuntMin |
| feed | 먹이 12회 먹기 | roundCounts.feeds ≥ N | grazeEfficiency(diet) > SIM.grazeMinEff |
| birth | 새끼 2마리 탄생 | roundCounts.births ≥ N | 항상 |
| pop | 무리 M마리 이상으로 마치기 | 종료 시 내 종 수 ≥ M | 항상 (M = max(8, 시작 수 − 1)) |

- N 초깃값 제안: hunt 2 · feed 12 · birth 2 (전부 `GAME` 상수로, 라운드 16초·1x 기준. 프로브로 보정).
- 시대가 오르면 N 을 올릴지는 이번 슬라이스에서 **하지 않는다**(일단 고정 — 난이도는 관문이 맡는다).

**선택 규칙 — ⚠ 결정론 함정이 여기 있다.** 시험 선택을 **기존 rng 스트림에서 뽑으면 안 된다.**
카드·월드 스트림이 한 칸 밀리면 밸런스가 통째로 이동한다(known_issues "rng 스트림을 늘리면 분포가
통째로 이동"). **시드 파생 해시로 뽑는다**: `hash(runSeed, era, stageIdx) % 후보수` 방식(어떤 스트림도
소비하지 않음). 같은 시드 = 같은 시험(재현 가능, `?seed=` 디버깅 유지).

## B. 계수기 — sim 이 세고, 게임은 읽기만 한다 (표시=실물 원칙)

`world.roundCounts = { hunts: number, feeds: number, births: number }` — **내 종만**, 새 월드마다 0.

세는 자리(사건이 판정되는 바로 그 줄 — 다른 곳에서 재유도 금지):
- `hunts`: `behavior.ts`의 `devour()` 안, `e.species.isPlayer`일 때 +1 (알파든 무리든 내 종의 처치면 인정).
- `births`: 번식 신생아 push 두 곳(`behavior.ts` 일반 번식 + 산 보물 대박), 내 종만.
  ⚠ **드래프트 스킵 보상 brood(world.ts의 무리 중심 일괄 스폰)는 넣지 말 것** — 넣으면 "스킵이 곧
  합격"이 되어 시험이 카드 선택을 뒤틀어 버린다.
- `feeds`: 채집 섭취가 확정되는 지점(`behavior.ts`에서 먹이를 소비해 에너지를 얻는 곳 —
  `grazeEfficiency` 사용처를 grep 하면 나온다), 내 종만.

정수 증가만 한다 — rng·부동소수점 불변이므로 **golden 결정론 지문은 절대값 그대로 통과해야 한다.**
바뀌면 계수기 구현이 틀린 것이다(테스트가 감지기).

## C. 판정과 불씨 — game 층 (sim 은 모른다)

- `Game.embers`: 시작 `GAME.emberStart = 5`, 상한 `GAME.emberMax = 5`.
- 증감: forage 불합격 **−1** · 보스 **격퇴** +1 · 시대를 넘기면 +1 (상한까지).
  버티기 통과·멸종 생존은 ±0 (지금과 동일한 "그냥 통과").
- **0이 되면 런 종료** — `endRun("lose")` 경로에 사유를 실어 결과 화면 요약에
  "혈통의 불씨가 꺼졌습니다"가 뜨게 한다(개체 수 0 멸종과 문구로 구분).
- 개체 수 0 즉시 멸종은 **기존 그대로**(불씨와 별개의 죽음).
- 판정 시점: `game.ts finishStage`(bossDefeated 플래그가 이미 있는 자리)에서 시험과 roundCounts 비교.
- 수치는 전부 `config.ts`의 GAME 에 두고 "프로브·폰 튠 대상" 주석을 단다.

## D. 표시 — 전부 기존 그릇 재사용 (새 상시 UI 금지)

- **goalBar(관전 중)**: 평시 목표 줄("무리를 먹여 키우세요")을 시험으로 교체 —
  주 줄 "이번 시험: 사냥 2회 (1/2)", sub 줄 끝에 불씨 점 "불씨 ●●●○○"(텍스트 점이면 충분, 새 위젯 금지).
  진행 숫자는 `world.roundCounts`를 그대로 읽는다.
- **라운드 끝**: `highlights.flash` — 합격(라임 0x8fd14f 계열) / 불합격(호박 0xffba3a) +
  불합격 문구에 이유와 대가("사냥 1/2. 불씨 1을 잃었습니다").
- **드래프트(예고)**: `draftPanel`에 "다음 라운드: {시험 문구}" 한 줄. 관문 앞 드래프트면 기존 위협
  예고를 함께 — `game.preview`(위협 문자열)는 game 이 이미 만들고 presetPanel 에는 전달되는데
  **draft.show 에는 미배선**이다(main.ts onDraft). 이번에 같이 잇는다.
- **불씨 첫 등장 안내(1회)**: "불씨는 이 혈통의 남은 기회입니다. 시험에 지면 하나 꺼집니다."
- 문구 규칙: 쉬운 말 · 한글 사이 em dash 금지 · 표준 안내체 · "불씨"는 처음 나올 때 한 번 풀이.

## 검증 (완료 조건)

1. `npm run typecheck` · `npm test`(golden 절대값 무변 포함) · `npm run smoke` · UI 수정 시 `npm run overlap`.
2. **프로브: 프리셋 8종 × 시드 여러 개로 forage 합격률 측정.** 어떤 프리셋이 0% 또는 100%면 시험
   수치가 틀린 것 — **대략 60~90% 구간**을 목표로 N 보정(불합격이 가끔 있어야 불씨가 산다).
3. 폰 실기: "라운드가 긴장되는가, 불합격이 아프되 납득되는가, 예고 덕에 카드 선택이 달라지는가."

## 열린 결정

- **구현자가 정해도 되는 것**: N 초깃값 미세조정, 문구 세부, 불씨 점의 모양.
- **사용자에게 물을 것**: ① "불씨"라는 이름(다른 이름을 원할 수 있다) ② 불씨가 너무 빨리 닳는다고
  느껴질 때의 방향 — 수치 완화냐, 회복 수단 추가냐(회복 수단은 새 시스템이라 스코프가 커진다).

## 후속 후보 (이 슬라이스가 폰 판정을 통과하면)

1. **이산 시너지 문턱** — 형질 조합이 "켜지는" 순간(예: 속도 60+무리 60 → 몰이 사냥). sim 행동 신설이라
   프로브 필수. backlog "극단값 설계"와 합칠 것.
2. **지도 칠하기** — 서식 범위가 지도에 남는다(축적의 가시화, 전염병 주식회사 항목).
3. 라운드를 가로지르는 장기 항목 1개(문명의 "겹치는 타이머" — 예: 3라운드 뒤 결실 카드).
