# 2026-07-20 세션 로그

## 요약
데스크톱에서 글자·UI 가 너무 작다는 피드백 수정. 창 높이에 비례한 UI 확대 배율(--ui-zoom)을
도입해 DOM 오버레이 전체와 화면 픽셀 Pixi UI(미니맵·배너·보스 바·하이라이트)를 같은 배율로 키웠다.
1080p 전체화면 기준 약 1.35배. 모바일·작은 창은 그대로(배율 1).

## 주요 변경
- `src/config.ts` — `uiScale(isDesktop, screenW, screenH)` 추가. 높이/750, 폭/900 가드, 상한 1.7.
- `src/ui/panelStyles.ts` — `body[data-layout="desktop"] > :not(#app) { zoom: var(--ui-zoom) }`
  (body 직속 오버레이 전부 한 규칙으로 확대, 캔버스만 제외). `.draft-popup` 데스크톱 max-height 의
  vh 를 배율로 나눠 보정.
- `src/main.ts` — `applyUiScale()`: CSS 변수 세팅 + Pixi UI 4종 `setUiScale`, resize 때 재계산.
  highlights/threatBanner/raidBossBar `update()` 에 화면 크기를 배율로 나눈 "논리 화면"을 넘김.
- `src/render/minimap.ts` — `setUiScale`(컨테이너 스케일 + place/containsScreenPoint 배율 반영).
- `src/render/threatBanner.ts` · `raidBossBar.ts` · `highlights.ts` — `setUiScale`(컨테이너 스케일
  + Text.resolution 을 배율만큼 올려 확대 흐림 방지).

## 결정 사항
- **DOM 은 CSS zoom 한 규칙, Pixi 는 컨테이너 스케일 + 논리 화면 전달** 방식 채택. 컴포넌트별
  폰트 크기 수정(수십 곳) 대신 배율 한 값으로 전부 커버 — 폰 기준 디자인이 그대로 유지된다.
- **zoom 아래 vh/vw 동작을 Playwright 로 실측**: 전체화면(inset:0)·퍼센트·중앙정렬은 정확하지만
  **vh/vw 는 배율만큼 커져 화면을 넘친다** → vh 쓰는 규칙(.draft-popup)만 `100vh / var(--ui-zoom)` 로
  보정. panelStyles 주석에 이 함정을 남겼다(새 규칙 작성 시 주의).
- 배율 공식: `min(1.7, max(1, min(h/750, w/900)))`. 좁고 긴 창에서 과확대 방지용 폭 가드 포함.
