- **카드 풀 52장**(특성 45 + 열쇠 7). 특성 카드 id 는 `pk_<특성id>`.

## 결정 사항

- **조건부 효과를 「파생 단계(A)」가 아니라 「쓰는 자리(B)」에 뒀다.** 제안서의 추천은 A 였는데,
  실제 구조를 보니 **A 가 불가능했다**: `traits` 는 개체가 태어난 시점의 스냅샷이라
  「밤에」·「수풀에서」처럼 상황마다 켜졌다 꺼지는 값을 담을 수 없다.
  대신 A 의 목적(단일 진실)은 지켰다 — 규칙·문구·등급이 전부 `perks.ts` 한 곳에 있고,
  sim 은 `perkMul(perks, 축, 맥락)` 하나만 부른다.
- **물기는 결과(피해·치명 확률)에 곱한다.** 능치(attack/defense)를 키워 `biteOutcome` 을 다시
  돌리면 ① 판정이 비선형이라 카드에 적힌 배수와 실제가 갈리고 ② 3단(90) × 1.5 = 135 로
  **「이빨 4단의 규칙 면제」를 카드 한 장이 사 버린다** ③ 화면의 관계 표식과 갈린다.
- **「받는 피해」축만 1 아래가 이득**(기운 소모와 같다). 「버티는 힘 ×1.5」라 적고 0.67 을 곱하면
  거짓말이라, 화면에 **실제로 곱해지는 수**를 적는다.
- **축 라벨을 `tiers.tierLine` 과 겹치지 않게 골랐다** — 티어 줄의 「무는 힘」·「버티는 힘」은 능치의
  배수인데 특성은 결과의 배수다. 같은 낱말이 두 가지를 가리키면 어휘가 갈라진다.
- **`tiers` 프로브를 되살리지 않았다.** 「카드가 쌓는 도장」만 재던 자라 v9 에는 잴 대상이 정의상 0 이다.
  없는 자를 있는 척 남기면 다음 사람이 그 출력을 근거로 쓴다.
- **시대 보상의 강화가 사라진 채로 뒀다.** 방울 보상으로 옮기는 것이 맞지만, 값을 여기서 지어내면
  근거 없는 밸런스 상수가 하나 생긴다(이 저장소가 네 번 데인 자리) → backlog 1번으로 넘겼다.

## 세션 2 · 폰 검토가 방향을 뒤집었다

### 요약
배포된 v9 을 사용자가 폰에서 보고 **방향이 틀렸다는 것이 드러났다.** 조건부 배수 45장은
「~할 때 ~ 몇 배」 일색이라 매력이 없고, 무엇보다 **티어와 카드의 역할이 뒤바뀌어 있었다.**
UI 버그 하나(목표 줄이 길어지면 옆 버튼이 세로로 늘어남)를 함께 고쳤다.

### 사용자가 지적한 것
- **"다 너무 ~할 때 ~ 몇 배 이런 식이라 좀 직관적이지도 않고 매력도 없네."**
- **"'공짜 점심은 없다' 정신과 '하이 리스크 하이 리턴'이 구현되지 않은 건 좀 아쉽네."**
- **"방울로 올리는 티어가 카드를 해금해준다는 알림도 없고, 그것 때문에 티어를 올려야겠다는 생각도
  안 들어. 내 원래 계획은, 티어를 올리면 더 좋은 카드, 더 특별한 카드들이 열려서 그걸 위해 티어를
  올리는 거고 그에 따라오는 티어 자체의 보상은 카드에 비해서는 소소한 정도였는데, 지금은 좀
  뒤바뀐 느낌이잖아."**
- 왼쪽 위 목표 줄이 길어질 때 칸이 잘리고, 옆의 방울 칸·일시정지 버튼이 못생겨진다.

### 무엇이 잘못됐나 (내 진단)
**「카드에서 도장을 뺀다」를 받고 그 빈자리를 혼자 채웠다.** 조건 13 × 축 8 조합표로 45장을
찍어냈으니 전부 같은 문법이 된 것은 필연이다. 그리고 `perks.ts` 에 **「대가를 안 붙인다 · 조건
자체가 대가다」를 규칙으로 못박아** 「공짜 점심은 없다」를 구조적으로 막아 놨다 — 그건 사용자가
정한 것이 아니라 내 판단이었는데 파일 머리에 여섯 계명 중 하나로 적혀 있었다.

역할이 뒤집힌 것도 같은 뿌리다: 티어가 파생 능치 전부를 주고 카드는 소소한 배수를 주는데,
사용자 계획은 **정확히 반대**였다.

### 확정된 다음 방향 (**[사용자 2026-08-10]**)
- **카드는 「고유 효과 + 대가」다.** 45장 → **20~25장**. 한 장 한 장이 sim 에 자기 규칙을 갖는다.
- **카드는 티어로 잠긴다.** 티어를 올릴 이유가 그것이다. **티어 자체 보상은 소소해져야 한다.**
- **해금 예고는 티어 구입 화면에서 2단계로**: 이름만 먼저 보여 주고, **그 티어 버튼을 한 번 더
  누르면** 카드 상세가 열린다.
- 상세는 backlog 최상단 「1. 카드 재설계 2차」에 적어 뒀다.

### 고친 것
- `src/ui/goalBar.ts` — `.goal-head` 를 `align-items: stretch` → `center` 로. 실측으로 확인한
  증상: 할 일 문구가 두 줄이 되면 알약이 51 → 69px 로 커지는데 **방울 칸과 멈춤 버튼이 함께
  69px 로 늘어나** 세로로 길쭉해졌다. 이제 둘 다 44px 고정이다.

  「한 줄 ellipsis」라 적어 놓고 실제로는 **줄 수 제한 없이 늘어났다.**

### 밟은 함정 (known_issues 에 기록)

## 세션 3 · 티어가 카드를 연다 (재설계 2차 착수)

### 요약
사용자와 카드 구조를 합의하고 **「티어를 올리면 카드가 열린다」를 구현했다.** 듀오 10개도 자동 발동에서
드래프트 카드로 옮겼다. 카드 내용(3·4단 고유 효과)은 아직이지만 **구조는 돈다.**

### 합의된 것 (**[사용자 2026-08-10]**)
- **카드 = 고유 효과 + 대가.** 전설 예시(「죽지 않는 것」 · 기운이 다해도 한 번은 안 죽는다 /
  되살아난 뒤로는 새끼를 못 친다)를 특히 마음에 들어 했다.
- **흔함을 늘리고 효과는 미미하게** — 그래야 귀한 카드의 값어치가 산다.
- **칸 수: 1단 4~7 · 2단 3 · 3단 2 · 4단 2** (내가 「위로 갈수록 적게」를 추천하고 근거 셋을 댔다:
  4단은 도달이 드물어 여러 장 만들면 아무도 못 본다 · 위쪽은 한 장이 sim 분기라 비싸다 ·
  4단은 원래 한 장이 판을 바꾸는 자리다). **하한 2장 보장.**
- **듀오를 카드로 바꾼다** — 내가 제안했고 사용자가 채택. 자동 발동이라 「켜진 순간이 안 읽힌다」던
  backlog 항목이 통째로 해소된다.
- **해금 예고는 티어 구입 화면에서 2단계**: 이름만 → 한 번 더 누르면 상세.

### 주요 변경
- **`sim/perks.ts` 게이트(`PerkGate`)** — `{ tiers?: [{cat,tier}], key? }` 하나로 보통 카드·듀오·
  열쇠 듀오를 전부 표현한다. `gateOpen` 을 **드래프트 필터와 화면 예고가 같이 쓴다.**
- **`GATES` 배치표** — 51장이 1~3단에 어디 있는지 한곳에 모았다. 「무리를 파면 뭐가 열리지?」의 답이
  표 하나다. 다리·눈이 3장씩 모자라 배수 카드 6장을 새로 만들어 칸을 맞췄다.

### 카메라 (병렬 갈래 · 완료)
`scripts/camera-probe.mjs` 를 새로 만들어 **먼저 쟀다.** 원인 셋을 갈라 확인:
- **목표점이 떤다 — 주범.** 무리 초점의 이동 방향이 초당 4.2회(1배속)~10.4회(3배속) 뒤집히는데
  카메라가 그 경로의 90~93%를 그대로 베끼고 있었다(저역통과도 데드존도 없었다).
- **프레임률 보정이 근사식 — 부차.** `min(1, dt·ease)` 는 dt 가 길수록 과다 보정(33ms 에서 +16%)이라
  프레임이 흔들리는 폰에서 튐 크기가 프레임마다 달라졌다.
- **sim 스텝 양자화 — 주범 아님**(스텝 프레임과 사이 프레임의 이동 비 1.07배). 후보에서 뺐다.
- 곁들여 **맵 크기가 문지기**임이 숫자로 확인됐다: 진도 0(맵 = 화면)에서는 카메라가 클램프에 붙어
  이동량이 문자 그대로 0 이다. 제보의 「맵도 넓어지니까」가 여기서 맞는다.

처방 셋(초점 저역통과 83ms · 데드존 22 논리px · 지수식 이징)을 **자동 추종에만** 걸었다.
실측(3배속 = 제보 상황): 떨림 **0.94 → 0회/초** · 가속도 잡음 −77% · 잔떨림 RMS 0.48 → 0.22px.
**대가는 뒤처짐**(초점과의 거리 5 → 22px) · 폰에서 「가운데에서 밀려난 느낌」이면 `CAM_DEADZONE` 을 18로.

### 다친 개체 기운 선
`woundTicks` 가 도는 동안만 머리 위에 뜬다. **기운이 낮다고 그리면 굶주린 개체가 전부 켜져** 평소
화면이 난잡해진다 — 그건 사용자가 싫다고 한 바로 그 그림이다. 물린 직후가 가장 진하고 아물며 옅어진다.
⚠ 이 표시는 **전투 재설계와 한 몸**이다(옛 값에서는 사냥이 0.17초에 끝나 선이 뜨기도 전에 사라졌다).
⚠ 선이 그려지는 것은 스크린샷으로 확인했으나 **크기가 폰에서 적절한지는 실기로만 판정된다.**

### 배포 직전에 잡은 blocker
git 이 미니맵을 `minimap.ts`(소문자)로 추적하는데 **실제 파일은 `miniMap.ts`** 였다. 윈도우·맥은
대소문자를 안 가려 안 드러났지만 **GitHub Pages 빌드는 리눅스에서 돈다** — import 를 실제 이름으로
고친 채 배포했다면 그 순간 빌드가 깨졌을 것이다. `git mv` 로 추적명을 실제 파일명에 맞췄다.
